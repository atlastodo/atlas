# AGENTS.md

## Working with the user (standing instruction)

- Before planning work on a bug, ask questions until the bug is properly understood (symptoms, reproduction, expected vs actual).
- Also ask questions about the proposed solution before implementing — don't assume intent.

## Dev environment

- All dev commands (`dev`, `web:dev`, `mobile:dev`, `desktop:dev`, `nix:bun-lock`, `test:all`, `lint`, `fmt`, `db:migrate`, `db:reset`, `version:bump`, `screenshots`, …) are devenv scripts defined in `devenv.nix` — run them inside `devenv shell`. The root `package.json` has **no** scripts; there is no root npm/bun task runner. (The full-suite script is `test:all`, not `test`: a script named `test` collides with the shell builtin and `devenv shell test` silently no-ops.)
- Bun is the package manager (`bun.lock` committed; CI installs with `--frozen-lockfile`); Node 26 is the runtime (devenv, `engines`, CI and the Docker image). Bun is pinned to **1.4.2** everywhere — devenv (via the nixpkgs snapshot in `devenv.lock`), `BUN_VERSION` in `.github/workflows/*.yml`, and `ARG BUN_VERSION` in `docker/Dockerfile` — bump them together.
- Postgres runs as a devenv service: `devenv up`. Dev DB `atlas_dev`, test DB `atlas_test`, user/password `atlas`/`atlas`.
- `DATABASE_URL`/`TEST_DATABASE_URL` are derived from the port devenv actually allocated (`$PGPORT`), which may not be 5432. Keep DB config out of `.env` — it auto-loads and would shadow the derived URLs.
- The server refuses to start without `DATABASE_URL` + `JWT_SECRET`; copy `.env.example` to `.env`.
- `EXPO_PUBLIC_API_URL` defaults to `http://localhost:8080` (the Axum API).
- The Android SDK is opt-in (several GB): a gitignored `devenv.local.nix` containing `{ android.enable = true; }`, then re-enter the shell. Only the local native scripts (`emulator:*`, `mobile:android`, `build:android:local`, `build:android:aab`, `bundle:android:release`) need it, and they say so when it is off. Expo Go (`mobile:dev`) and EAS cloud builds don't.

## Verification

- `test:all` = full suite, in order: `cargo nextest run --workspace` → vitest in `packages/client-core`, `packages/shared` and `apps/electron` → jest in `apps/mobile`, under `set -euo pipefail` (the first failure stops it). `crates/atlas-server/tests/*` are integration tests that need Postgres up (they migrate `TEST_DATABASE_URL` themselves); `atlas-core` tests are Postgres-free.
- `lint` = `cargo fmt --check` + clippy (`--no-deps -D warnings`, as in CI) + `tsc --noEmit` for `packages/shared` and `apps/mobile` + `eslint .` (flat config in `eslint.config.mjs`: typescript-eslint recommended + react-hooks) + `prettier --check .` (`.prettierrc.json`, `.prettierignore`). `fmt` runs `cargo fmt` and `prettier --write .`. Note: CI (`Lint (TypeScript)`) also typechecks `packages/client-core` and `apps/electron` (via `bun run --parallel --filter '*' typecheck`), which local `lint` does not — run `cd apps/electron && bun run typecheck` when touching it.
- Runners are per-package, deliberately separate (not `bun test`):
  - Rust: `cargo nextest run -p atlas-server <name>` for one test. Every server test shares one database (`TEST_DATABASE_URL`), so a test that runs a database-wide sweep (op retention, blob GC, account purge) and asserts on what it removed must be listed in the `database-sweeps` group in `.config/nextest.toml`, which runs them one at a time; otherwise they delete each other's rows and flake.
  - `packages/*`, `apps/electron`: `cd packages/shared && bunx --bun vitest run src/foo.test.ts` (vitest runs under Bun's runtime, supported since Bun 1.4; `test:all` and CI do the same).
  - `apps/mobile`: jest-expo (`bun run test -- <pattern>`) — must run under real Node; under Bun's runtime it dies at load (`Attempted to assign to readonly property`).

## Layout

- `crates/atlas-core` — pure Rust domain logic (HLC and op log types), no I/O. Conflict resolution and recurrence live in TypeScript only (`packages/client-core`, `packages/shared`); their JSON fixtures in `test-vectors/` are read by those tests.
- `crates/atlas-server` — Axum + sqlx over Postgres. `migrations/` is the schema source of truth.
- `apps/mobile` — the single UI (React Native + Expo); the web app is the same code via react-native-web. `apps/electron` wraps the web export. Dynamic `accent-*` colors resolve to CSS variables (`--accent-<shade>` hex and `--accent-<shade>-rgb` channels from `@atlas/shared`) supporting Tailwind opacity modifiers (e.g. `bg-accent-100/60`, `dark:bg-accent-950/70`).
- `packages/client-core` — local SQLite/IndexedDB store + sync client; `packages/shared` — portable pure TS logic.
- Self-hosting: the root `compose.yaml` (project `atlas-todo`) only `include:`s `docker/docker-compose.yml`; run compose from the root so it reads the root `.env`. Server settings and defaults come from `crates/atlas-server/src/config.rs` (+ `ratelimit.rs`), mirrored in `.env.example` and `docs/self-hosting.md` — keep all three in step. The NixOS module mirrors no defaults: its `settings` passes env names through, and its first-class options, the reserved-name list and the socket `DATABASE_URL` form (validated against a live server) must track `config.rs`.
- The root flake builds `atlas-server`, `web-dist` and `atlas-desktop` from source (derivations in `nix/packages/`, also exposed as `overlays.default`), along with `nixosModules` (`services.atlas-todo`, `programs.atlas-desktop`, and `default` combining both) and `homeManagerModules` (`programs.atlas-desktop`). The JS builds read npm dependencies from `nix/bun.nix`, generated from `bun.lock` by bun2nix: run `nix:bun-lock` after every `bun.lock` change (`lint` fails when it is stale). `nix flake check` builds everything and runs the `server-vm` NixOS VM test (`nix/tests/server.nix`; needs KVM). `packages.<system>.web-dist` is what a `services.atlas-todo.staticDir` points at. The release desktop tarball still embeds its own flake (`nix/flake.desktop.nix` + `nix/flake.desktop.lock`, refresh with `desktop:flake-update`) for users pinned to it.
- `docs/android-permissions.md` is the allowlist of Android permissions: its "Declared" table is parsed by `apps/mobile/scripts/check-android-permissions.mjs`, which `release.yml` runs on the merged release manifest (locally: `android:permissions` after a release build) and which fails on any permission not listed, or listed but no longer declared. Unused permissions that dependencies add go in `android.blockedPermissions` in `app.json`.
- `docs/` holds the operator and architecture guides (`self-hosting.md`, `architecture.md`); `docs/screenshots/` is the README's images, regenerated by `screenshots` (`scripts/screenshots.mjs` seeds a demo account through the web UI on a throwaway server and database, moving the browser clock for the habit and stats history).
- `dist-desktop/` and root `atlas-desktop-*.tar.gz` are gitignored build artifacts — don't edit or commit them.
- The pre-sync REST entity CRUD (task/project/section/label endpoints over the relational tables) was removed on 2026-09-21: the client data path is the sync op log exclusively. What remains of `projects.rs` is the E2EE key-distribution routes (`PUT /projects/:id/keys`, `PUT /projects/:id/member-keys/:member_id`, `GET /project-keys`, `GET /project-keys/missing`); membership/invites (`members.rs`) are unchanged. The relational `tasks`/`projects`/`sections`/`labels`/`task_labels` tables are dropped by `20260926000026_drop_orphaned_entity_tables.sql`; their creating migrations stay (append-only history). `project_members`, `project_keys` and `blobs` keep `project_id` as a bare UUID with no foreign key.

## CI & release (GitHub Actions)

- The release's Android build reads caches (Gradle, NDK/CMake, ccache: `.github/actions/android-setup`, shared flags in `.github/scripts/android-gradle.sh`) that only `android-cache.yml` writes, on `main` (push, weekly, manual): a tag run can't read caches another tag saved. Keep the two builds' flags and env identical, or the caches miss.
- Release pipelines of two tags running at once race at the Play upload: the lower `versionCode` is refused once the higher one is on the track.
- CI is `.github/workflows/`. Default branch is `main`; pre-releases are cut on the long-lived `dev` branch (see below). Commit messages follow Conventional Commits (`feat:`, `fix(mobile):`, …). A commit that fixes an issue puts `Fixes #N` (one line per issue) in its body: PRs target `dev`, where GitHub ignores closing keywords, so the keyword must travel with the commit and closes the issue when it reaches `main` with the next stable release. Don't rely on the PR description for this.
- `ci.yml` runs on push to `main`, on PRs, and when `release.yml` or `dev-image.yml` calls it. Jobs (check names): `Lint (Rust)`, `Lint (TypeScript)`, `MSRV` (Cargo `rust-version`, 1.94), `Test (Rust)` (Postgres 16 service), `Test (TypeScript)`, `Test (mobile)`, `Audit (Rust)` (cargo-deny), `Audit (JS)` (`bun audit`). A `changes` job picks the jobs by changed paths: Rust jobs for `crates/`, `migrations/`, `Cargo.*`; TS/mobile jobs for `packages/`, `apps/*`, `bun.lock`; Lint (TypeScript) for anything outside the Rust tree (Prettier covers docs). The audits and MSRV run when manifests or lockfiles change and weekly (Monday cron); a tag, a manual run or a release runs everything. A newer push cancels the running one. Branch pushes whose head commit starts with `chore(release):` skip CI; the tag run tests that commit.
- Dependabot (`.github/dependabot.yml`): weekly version updates for Actions, Cargo, Bun and Docker, grouped minor/patch, targeting `dev`. Security updates are on as a repo setting and always target `main`: merge one there, then merge `main` back into `dev`. Dependabot doesn't update `nix/bun.nix`; `dependabot-bun-nix.yml` regenerates it on its bun PRs and pushes to the PR branch.
- The two audits are `continue-on-error` on purpose. The known unfixable advisories (`braces`, `node-forge`: no patched release yet) are analyzed in `//audit-known` in the root `package.json` — read it before chasing audit findings; fixable advisories go in `overrides`, never an ignore list.
- Branches: work lands on `dev`; `main` is stable-only. A plain push to `dev` publishes only the moving `dev` Docker tag (`dev-image.yml`: CI for the changed paths, then the image on GHCR and the Docker Hub mirror; skipped for `chore(release):` commits and docs-only pushes); nothing else is published without a tag. Cut a pre-release by hand on `dev`: `version:bump X.Y.Z-rc.N`, commit `chore(release): vX.Y.Z-rc.N`, tag, push `dev` and the tag. `main` takes no direct pushes (ruleset "main: PRs only": a PR from `dev`, merge commits only, CI required, no bypass). To ship: on `dev`, `version:bump X.Y.Z` and commit `chore(release): vX.Y.Z`; open a PR `dev` → `main` and merge it; tag the merge commit on `main` `vX.Y.Z` and push the tag; then fast-forward `dev` to `main` (rc and stable tags can't collide: the versionCode below). There is no dev server; app.atlastodo.dev stays on stable releases.
- Versioning is lockstep: never hand-edit a version in one manifest. Use `version:bump [--no-notes] [--desktop] <x.y.z|patch|minor|major>` (updates all package.jsons, `app.json`, `bun.lock`, Cargo manifests, regenerates `nix/bun.nix`, and regenerates `RELEASE_NOTES.md` when the version changes (a stable release lists commits since the last stable tag, so it carries what its rcs did; an rc lists commits since the last tag of any kind); `--no-notes` skips that, `--desktop` also builds the desktop tarball locally), commit as `chore(release): vX.Y.Z`, tag `vX.Y.Z`, push `main` and the tag. Only `X.Y.Z` and `X.Y.Z-rc.N` are accepted (`patch|minor|major` need a stable current version). Cargo, npm and Android's versionName take the rc string as is. The Android `versionCode` is derived, not incremented, by `scripts/version-code.mjs`: `major*1000000 + minor*10000 + patch*100 + slot`, slot = `N` for `-rc.N` (1-98) and 99 for stable, so it rises across rc and stable builds (0.1.4-rc.1 = 10401, 0.1.4 = 10499; minor and patch < 100). The Prepare job re-derives it and fails on a mismatch. Releases up to v0.1.3 used +1 codes (81 for v0.1.3), all far below. iOS has no separate marketing version, so an iOS build of an rc would carry the rc string (none is published).
- A `v*` tag runs `release.yml`: `CI` → `Prepare` (the tag must equal the package.json version; extracts the notes; **fails unless all four `ANDROID_*` keystore secrets are set**) → `Docker` (the reusable `docker.yml`, shared with `dev-image.yml`): `Docker image (<arch>)` per architecture, pushed by digest (arm64 only when the repo is public: its hosted runners are free only there; per-arch `buildcache-<arch>` tags) → `Docker image` merges them into the multi-arch `ghcr.io/<owner>/<repo>` with the OCI metadata from `IMAGE_METADATA`, and mirrors it to Docker Hub as `vars.DOCKERHUB_IMAGE` when that and the `DOCKERHUB_*` secrets are set and the repo is public; plus `Android APK + AAB`, `Desktop tarball` → `GitHub Release`. Secrets and variables are listed in `apps/mobile/RELEASE.md`. A tag containing `-` is a prerelease: a GitHub prerelease (`--latest=false`), Docker tag `X.Y.Z-rc.N` (never `latest`, on Docker Hub too), the AAB to the Play **internal** track (`PLAY_STORE_PRERELEASE_TRACK`, default `internal`; stable goes to `vars.PLAY_STORE_TRACK` and internal, one upload), no `atlas-desktop-latest.tar.gz`.
